# Primary (Darasa la IV / STD4) council + region report generators (v1)

This change replicates the secondary report pipeline for primary STD4 schools: 14 new self-contained report directories (6 under `reports/primary/council/`, 8 under `reports/primary/region/`), each with its own `template.html.j2`, `style.css`, coordinate-based `scripts/extract_primary_*.py`, `data*.json`, `reference/original*.pdf`, and committed `output/`. The JSON→Jinja2→WeasyPrint→`compare.py` fidelity harness is unchanged; the only shared-code edit is an additive regex in `sars_pdf/grading.py` that recognises the Swahili `Daraja X (...)` competency label alongside `Grade X`. `build_all.py` gained `--level`/`--scope` discovery for `reports/primary/**`. A handful of genuinely-distinct source structures were deliberately deferred under the user's time-box directive and documented rather than built.

Watch for: the secondary regression guard holds — re-rendering two of the four affected secondary reports produces byte-identical `output/report.html` and `report.pdf` (**confirmed**). All 18 primary render jobs match source page counts exactly, including the previously-buggy region top-10-schools now at 5/5 (**confirmed**). No primary page clears the strict ≥96% bar; this is honestly attributed to the proprietary-Arial glyph floor and matches the committed comparison READMEs (**confirmed**). One minor documentation nuance: the INDEX prose references `Arial Narrow`/`Times New Roman` families, but every primary `style.css` registers only `Arial` (regular+bold) mapped to Liberation Sans — no defect, just an over-broad prose claim (**confirmed**).

**Verdict**: APPROVED

## High-level view

The shared-code blast radius is a single additive function branch in `grading.py`. The `Grade X` regex is tried first, the new `Daraja X` regex second, then the unchanged GPA-band fallback; secondary and lakezone labels are all `Grade X`, so they never reach the new branch. `render.py` is byte-identical to base — a mid-task change that leaked a data-driven competency fill into four secondary summary cells was reverted (1c17b3c) and replaced by stamping an explicit `level` inside the primary extractors' `data.json`, keeping extraction the single source of truth.

Page fidelity is data-driven throughout. Every extractor walks the source with pymupdf words and assigns columns by measured x-centres; pagination is reproduced from the source's own block/page structure (e.g. `page_top` flags per section) rather than hard-coded row counts. The one real 6-vs-5 pagination bug on region top-10-schools was fixed by this data-driven grouping and now matches 5/5.

Fonts are registered as bare single family names with inline `@font-face` pointing at the repo's Liberation TTFs; no `@import`, no comma fallback chains. Generated PDFs embed only `Arial`/`Arial-Bold` subsets — never Noto.

The fidelity claims are honest: no page passes the strict ≥96% bar, and the INDEX explains why (proprietary Monotype Arial vs metric-compatible Liberation glyph noise, region decorative-legend/untinted-body residual, and non-uniform row-packing pagination drift). The numbers in INDEX match the committed `output/comparison*/README.md`. Deferred council/region source structures are listed explicitly as NOT built.

### Additive Daraja regex cannot touch secondary output

`competency_letter` now searches for `Grade X` first, then `Daraja X`, then falls back to the GPA band. Secondary and lakezone competency strings are the English `Grade X` form, so they match on the first branch and never reach the new `_DARAJA_RE` path. The change is purely additive — a new `elif`-style second search plus a new compiled regex — and the diff under `sars_pdf/` and `reports/secondary/` is confirmed to be *only* this file (`git diff … --stat -- reports/secondary/ sars_pdf/` shows `sars_pdf/grading.py | 8 ++++++++` and nothing else).

The stronger guarantee comes from re-rendering. `render.py` is byte-identical to base (the 1c17b3c revert netted its earlier edit to zero). Re-rendering two of the four reports that carry `lvl-*` summary/total cells — `council-subjects-rank` and `council-schools-rank-overall` — into their committed `output/` produces no git diff on either `report.html` or `report.pdf`. The regression that the orchestrator caught (a data-driven competency fill leaking into secondary summary cells) is closed: the fix moved the explicit `level` into the primary extractors' `data.json` via `grading.competency_letter`, so the colour is carried by primary data, not computed at render time for everyone.

### Data-driven pagination, no hard-coded page counts

The region top-10-schools source packs two `SHULE KUMI ...` blocks per page across 5 pages and mixes two physical layouts (a WAV/WAS/JML division grid on source pages 1–3, a per-subject AL/DRJ marks grid on pages 4–5). The extractor decides layout per section from the S/N x-position of the first data row and emits a `page_top` flag (true only for the first block on each source page); the template groups blocks onto pages from that flag. There are no hard-coded page numbers or per-page row counts in the template — the only `5` in the file is a prose comment. This is what took the earlier 6-vs-5 bug to an exact 5/5.

Across all 18 primary render jobs (including the multi-source `_serikali`/`_binafsi`/`_jumla` tags), generated PDF page count equals source page count exactly — 0 mismatches. The counts span 1 to 16 pages, so the pagination logic is exercised on both trivial and dense multi-page grids.

### Extraction is coordinate-based, values are display strings

The top-10-schools extractor (representative of the set) parses with `pymupdf` words, groups them into lines by y-band, and assigns each word to a column by nearest measured x-centre; there are no literal data rows embedded in the script. Competency is stored as the full Swahili label (`Daraja B (Vizuri)` etc.) and an explicit single-letter `level` is stamped from it via `competency_letter`, so only the `KUNDI LA UMAHIRI` cell colour is data-driven. A walk of `primary-council-subjects-rank/data.json` finds zero non-boolean numeric leaf values — every score is a display string — and eight `Daraja X (...)` labels with their `level` stamped.

### Fonts: single-family Liberation, no fallback, no Noto

Every primary `style.css` registers `@font-face` families under bare single names (`'Arial'`), with `src: url("../../../../fonts/Liberation*.ttf")`, no `@import`, and no comma-separated fallback chains. In practice the primary reports register only `Arial` regular and bold (mapped to Liberation Sans) — the INDEX prose additionally names `Arial Narrow` and `Times New Roman`, which describes the *originals'* embedded faces, not what the templates register. Harmless, but the prose reads as if those families are used in the reports. All 18 generated PDFs embed only `Arial`/`Arial-Bold` subsets; a scan for `Noto` across every page of every generated PDF returns zero.

### Fidelity claims match the committed comparisons

No primary page clears the strict bar (tolerant-diff ≤ 4% AND zero fill diffs AND zero word diffs), and the INDEX says so — every verdict row is `0/N`. Spot-checking the committed READMEs against the INDEX table: subjects-rank INDEX lists tol 8.83% / 1 orig-only fill `#fed4fc` / words 26/28, and the README shows 8.86% / `#fed4fc` / 26/28; region top-10-schools INDEX lists tol 14.8–17.1% / fills 3–10 orig 1–2 gen, and the README shows 14.75–17.13% across pages with matching fill counts. The residual explanations — proprietary Monotype Arial vs Liberation glyph floor (the same floor the genuine-Arial lakezone example hits at 0/11), region decorative-legend/untinted-body fills, gen-only competency greens that pdfplumber can't match as rects, and non-uniform row-packing pagination drift — are consistent with the failing dimensions the READMEs name. The only discrepancy is sub-0.1% rounding on a couple of tolerant figures.

### Deferred sources are documented, not overclaimed

The INDEX Coverage status lists the council sources still deferred (`SCHOOL RANK UFAULU ALAMA`, `10 BEST SCHOOLS GRADING`, the two `KIMASOMO` per-subject top-10s, `KATA RANK ALAMA`) and the region sources deferred (the 3pp `MKOA UFAULU MASOMO STD4 2026` variant, `HALMASHAURI STD4 JUMLA 2026`, `KATA STD4 JUMLA 2026`), each with a one-line reason for why it is a genuinely distinct structure. None of these appear as a built report dir. FEAT-002 and FEAT-004 findings also record the deferrals. Under the user's explicit time-box directive this is an accepted scoping decision, and it is reported honestly rather than as completed work.
